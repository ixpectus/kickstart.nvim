Как читать этот план

Вы не будете писать код руками. Ваш формат: читать существующий код → задавать вопросы → получать объяснение. Этот план — список тем, которые нужно проработать в таком формате, привязанный к конкретным строкам вашего кода.

Каждый шаг — это тема. Внутри: исходный код (ваш, реальный), ваши вопросы (то, что вы спрашивали), и что конкретно нужно понять. Порядок — от фундамента к специфике.

Рекомендуемый темп: 1 шаг в день, по 30–60 минут. Читаете код, задаёте вопросы, закрепляете на практике (вызов команды → наблюдение результата).

ШАГ 1 ИЗ 6 · Фундамент Neovim API

vim.fn, vim.api, vim.bo — кто есть кто

В сессии вы спросили: "что такое vim.fn это типа неймспейса?", "то есть line это функция в nvim?", "а vim.bo это что", "vim.api это уже новое api neovim, а не обёртка над апи vim?". Это базовые вопросы о том, как устроен Neovim изнутри. Без ответа на них любой код — чёрный ящик.
functions.lua, строки 2–3, 8, 63, 80–81, 92, 97, 104, 126 -- functions.lua: все вызовы vim.fn
vim.fn.stdpath 'data'
vim.fn.strftime '%Y-%m-%d %H:%M:%S'
vim.fn.finddir('.git' .. '/..', ...)
vim.fn.line "'<"
vim.fn.line "'>'"
vim.fn.line '$'
vim.fn.expand '%:p'
vim.fn.getline(i)
vim.fn.input('Prompt: ', '')
vim.fn.setreg('+', payload)
commands.lua, строки 57, 65, 70, 74, 78, 114–127 -- commands.lua: все вызовы vim.api
vim.api.nvim_set_keymap
vim.api.nvim_buf_get_mark(0, '<')[1]
vim.api.nvim_create_user_command('PromptClear', ...)
vim.api.nvim_create_buf(false, false)
vim.api.nvim_set_current_buf(buf)
vim.api.nvim_buf_set_name(buf, '[PromptShow]')
vim.api.nvim_buf_set_lines(buf, 0, -1, false, lines)
vim.bo[buf].buftype = 'nofile'
vim.bo[buf].bufhidden = 'wipe'
Ваш вопрос: «что такое vim.fn это типа неймспейса?»
Нет, это не неймспейс. vim.fn — это таблица-обёртка, которая делает все встроенные Vimscript-функции доступными из Lua. vim.fn.line() вызывает Vimscript-функцию line(), обёрнутую в Lua-стиль. Это медленнее чем vim.api, потому что идёт сериализация данных между Lua и Vimscript.
Ваш вопрос: «vim.api это уже новое api neovim, а не обёртка над апи vim?»
Да. vim.api.nvim_buf_set_lines() — это прямой вызов C API Neovim из Lua. Без Vimscript, без сериализации. Быстрее, типобезопаснее. vim.fn.getline() — та же самая операция, но через Vimscript-слой (медленнее).
  • 1.1 Выучить таблицу: какие vim.* таблицы существуют и что каждая делает. vim.fn (Vimscript-обёртка), vim.api (C-API), vim.bo (буферные опции), vim.wo (оконные опции), vim.o (глобальные опции), vim.g (глобальные переменные). Не запоминать наизусть — понять принцип: vim.X — это разные таблицы с разными назначениями.
  • 1.2 Понять разницу vim.fn vs vim.api на конкретном примере: vim.fn.getline(1) читает строку 1 через Vimscript (медленно), vim.api.nvim_buf_get_lines(0, 0, 1, false) читает ту же строку напрямую из C (быстро). В вашем коде на строке 97 используется vim.fn.getline(i) — это допустимо для редких вызовов, но для частого кода — vim.api.nvim_buf_get_lines().
  • 1.3 Понять vim.bo[buf].buftype и vim.bo[buf].bufhidden: buftype определяет тип буфера ('' = обычный, 'nofile' = служебный, 'quickfix' = быстрый). bufhidden определяет, что происходит при переключении ('' = скрыть, 'wipe' = удалить, 'hide' = оставить в памяти). На строке 120–121 вы устанавливаете buftype='nofile' и bufhidden='wipe' — это делает буфер невидимым в :ls и автоматически удаляет при закрытии.

if #content > 0 then

Ваш вопрос: «что делает #chunks, что это за синтаксис»
#chunks — это оператор длины таблицы в Lua. Для массива (последовательности с индексами 1, 2, 3...) #chunks возвращает количество элементов. На строке 101 commands.lua #chunks возвращает количество чанков (групп строк). Это не «синтаксис» — это встроенный оператор Lua, как + или -.
Ваш вопрос: «что значат тут [[», «их используют в основном для того, чтобы не экранировать кавычки?»
[[...]] — это многострочная строка в Lua. Она позволяет писать текст с переносами, кавычками, процентами без экранирования. Основная ценность — не только кавычки, а возможность писать многострочные строки (шаблоны, SQL-запросы, HTML, форматы). В вашем коде на строках 111–117 functions.lua она используется для создания формата с переносами строк.
Ваш вопрос: «почему аргументы false, true», «почему тут такие параметры»
nvim_create_buf(false, false) — первый false = modifiable (можно ли редактировать), второй false = buflisted (показывать ли в :ls). nvim_buf_set_lines(buf, 0, -1, false, lines) — 0 = от первой строки, -1 = до последней, false = не строгий режим (не ошибка при выходе за границы), lines = массив строк для вставки.
  • 2.1 Оператор # в Lua: что возвращает для массивов, строк, смешанных таблиц. Почему #content на строке 41 functions.lua работает (проверка "есть ли запись в лог"), а #chunks на строке 101 commands.lua — количество чанков. Практика: прочитать код с # и предсказать, что вернётся.
  • 2.2 Многострочные строки [[...]]: когда использовать вместо '...'. На строках 111–117 functions.lua — многострочный шаблон для payload. На строках 62–66 commands.lua — многострочный mapping. Различать [[...]] (базовый) и [=[...]=] (вложенные скобки).
  • 2.3 Параметры функций Neovim API: nvim_create_buf(modifiable, buflisted), nvim_buf_set_lines(buf, start, end, strict, lines), nvim_buf_get_mark(buf, mark). Знать порядок и смысл каждого параметра — не угадывать.
  • 2.4 Таблицы в Lua (ipairs vs pairs, table.insert, table.concat): table.insert(lines, ...) на строке 98 functions.lua — добавление в массив. table.concat(lines, '\n') на строке 101 — объединение массива в строку. ipairs vs pairs на строке 19 commands.lua.
ШАГ 3 ИЗ 6 · Marks и визуальные режимы

'<', '>', nvim_buf_get_mark и vim.fn.line

В сессии: "vim.fn.line это функция, которая принимает аргумент '<'?", "что значит после выхода из визуального режима, в какой момент это происходит?", "получается при leader s я теперь не выхожу из визуального режима?", "почему не сработал вариант с fn.line". Это критически важная тема — непонимание приводит к багам «отправляется одна строка вместо диапазона».
functions.lua, строки 80–81, 86; commands.lua, строка 65 -- Фоллбек на marks (functions.lua, строки 80–81)
from = from or vim.fn.line "'<"
to = to or vim.fn.line "'>'"

-- Если marks = 0 (вне визуального режима), fallback (строка 86)
if to == 0 then
to = vim.fn.line '$'
end

-- Прямой вызов из visual-mapping (commands.lua, строка 65)
vim.api.nvim_buf_get_mark(0, '<')[1],
vim.api.nvim_buf_get_mark(0, '>')[1]
Ваш вопрос: «vim.fn.line это функция, которая принимает аргумент '<'?»
vim.fn.line("'<") — да, принимает строковый аргумент. '< и '> — это marks, которые Neovim автоматически устанавливает при выходе из визуального режима. vim.fn.line("'<") возвращает номер строки начала выделения. Но! Если вы НЕ в визуальном режиме — vim.fn.line("'<") вернёт 0.
Ваш вопрос: «получается при leader s я теперь не выхожу из визуального режима?»
Нет, всегда выходите. <Cmd>... на строке 65 commands.lua — это Ex-команда, которая автоматически завершает визуальное выделение перед выполнением. <cmd>... (строчные) — тоже. Разница в том, что noremap на строке 59 commands.lua означает "не обрабатывать маппинги внутри" — это не про выход из режима.
Ваш вопрос: «почему не сработал вариант с fn.line»
Потому что vim.fn.line("'<") возвращает 0 вне визуального режима. На строке 82–83 functions.lua — обработка: if from == 0 then from = 1. Но nvim_buf_get_mark() на строке 65 commands.lua — более надёжный способ: он работает даже если marks ещё не установлены (тоже вернёт {0, 0}, но с более явной обработкой).
  • 3.1 Marks '< и '>: когда Neovim их устанавливает (при выходе из визуального режима), что возвращает vim.fn.line("'<") вне визуального режима (0), как работает nvim_buf_get_mark(0, "'<") (возвращает {row, col}), почему на строке 65 commands.lua используется [1] для извлечения row.
  • 3.2 Разница vim.fn.line("'<") vs vim.api.nvim_buf_get_mark(0, "'<"): первый — через Vimscript-слой (медленнее, возвращает число), второй — через C API (быстрее, возвращает таблицу {row, col}). Когда какой использовать (строки 80–81 vs строка 65).
  • 3.3 Visual-mapping vs Normal-mapping: map('v', ...) на строках 63–67 commands.lua — работает только в визуальном режиме. map('n', ...) на строке 61 — только в нормальном. Почему <Cmd> завершает визуальное выделение, а noremap — нет.
ШАГ 4 ИЗ 6 · Жизненный цикл буфера

nvim_create_buf, buflisted, buftype, bufhidden, :bd

В сессии: "буффер не открывается", "потестировал, буффера нет в :ls", "какие есть опции у bufhidden", "что такое bd". Вы создаёте временный буфер на строках 114–127 commands.lua, но не понимаете, почему он не виден в :ls.
commands.lua, строки 113–128 local function OpenTemporaryBuffer(lines)
local buf = vim.api.nvim_create_buf(false, false)
-- ^modifiable=false ^buflisted=false
vim.api.nvim_set_current_buf(buf)
vim.api.nvim_buf_set_name(buf, '[PromptShow]')
vim.api.nvim_buf_set_lines(buf, 0, -1, false, lines)

vim.bo[buf].buftype = 'nofile'
vim.bo[buf].bufhidden = 'wipe'
vim.bo[buf].modifiable = false

vim.keymap.set('n', '', 'bd', { buffer = buf, silent = true })
vim.keymap.set('n', 'q', 'bd', { buffer = buf, silent = true })

end
Ваш вопрос: «потестировал, буффера нет в :ls»
Потому что на строке 114 nvim_create_buf(false, false) — второй false означает buflisted = false. Буфер не появится в :ls. Это намеренное поведение: вы создаёте служебный буфер, который не должен мешать. Если хотите видеть — nvim_create_buf(false, true).
Ваш вопрос: «какие есть опции у bufhidden», «что такое bd»
bufhidden — что происходит при переключении на другой буфер: '' (скрыть, оставить в памяти), 'hide' (то же), 'wipe' (удалить полностью), 'unload' (выгрузить, но оставить), 'swapfile' (сохранить swap). :bd (buffer delete) — команда удаления буфера. На строках 125–126 bd привязан к q и <Esc>.
  • 4.1 Полный жизненный цикл временного буфера: nvim_create_buf(false, false) → nvim_buf_set_name() → nvim_buf_set_lines() → vim.bo[buf].buftype = 'nofile' → vim.bo[buf].bufhidden = 'wipe' → vim.keymap.set() → bd. Понимать каждый шаг: что делает, почему именно так.
  • 4.2 Значения buflisted: true = буфер виден в :ls, false = скрыт. Когда использовать каждый. На строке 114 commands.lua — false намеренно.
  • 4.3 Значения buftype: '' (обычный), 'nofile' (без файла, служебный), 'quickfix', 'terminal'. Почему buftype='nofile' на строке 120 делает буфель невидимым для :edit и :next.
  • 4.4 Значения bufhidden: ''/'hide' (скрыть), 'wipe' (удалить), 'unload' (выгрузить), 'swapfile'. Почему 'wipe' на строке 121 — буфер удаляется при переключении, и почему это важно для временных буферов.
ШАГ 5 ИЗ 6 · Файловый I/O и обработка ошибок

io.open, readfile, mkdir, обработка ошибок

В сессии: "local f = io.open(PROMPTS_FILE, 'w') тут нужно чтоб файл создавался если его нет", "для чего нужна проверка if f then", "ошибка Unknown function: appendfile". Вы работаете с файлами на строках 18–24, 42–58 functions.lua.
functions.lua, строки 18–24, 42–58 -- Запись в лог (строки 18–24)
local f = io.open(GetPromptLogPath(), 'a')
if f then
f:write(entry)
f:close()
else
vim.notify('Failed to write to prompt log', vim.log.levels.ERROR)
end

-- Чтение лога (строка 38)
local content = vim.fn.readfile(log_path)

-- Архивация (строки 42–58)
local archive_f = io.open(archive_path, 'a')
if archive_f then
for _, line in ipairs(content) do
archive_f:write(line .. '\n')
end
archive_f:close()
end
Ваш вопрос: «local f = io.open(PROMPTS_FILE, 'w') тут нужно чтоб файл создавался если его нет»
io.open(path, 'w') — режим 'w' создаёт файл автоматически, если его нет. Режим 'a' (append) — тоже создаёт. io.open() возвращает nil, err_msg при ошибке (например, нет прав на запись в директорию). Поэтому проверка if f then — это не «создать файл если нет», а «если файл успешно открыт, записать; иначе — ошибка».
Ваш вопрос: «для чего нужна проверка if f then»
io.open() может вернуть nil (ошибка открытия файла). if f then проверяет: если файл открыт успешно — пишем. Иначе — vim.notify() об ошибке. Без этой проверки — crash при f:write() на nil.
Ваш вопрос: «ошибка Unknown function: appendfile»
appendfile() — такой Vimscript-функции не существует. В Lua для добавления в конец файла — io.open(path, 'a'). Режим 'a' (append) — стандартный способ.
  • 5.1 Режимы io.open(): 'r' (чтение), 'w' (запись, создаёт/перезаписывает), 'a' (добавление, создаёт). На строках 18, 42, 55 functions.lua используется 'a' (append) — файл создаётся автоматически, если нет. Понимать разницу между 'w' (перезаписывает) и 'a' (добавляет).
  • 5.2 Обработка ошибок io.open(): возвращает nil, err_msg при ошибке. if f then — проверка успешности. Альтернативы: assert(io.open(...)), pcall(). На строках 19, 43, 56 functions.lua — три места с проверкой.
  • 5.3 Разница vim.fn.readfile() vs io.open(): vim.fn.readfile(path) читает весь файл в массив строк (строка 38). io.open(path, 'r') — открывает файловый дескриптор, f:read('*a') — читает всё содержимое как строку. Когда какой использовать.
  • 5.4 Создание директорий: vim.fn.mkdir(path, 'p') — создание директории с вложенными. Где в вашем коде не используется (но может понадобиться для ~/.local/share/, если директория не существует).

Ваш вопрос: «ошибка ... attempt to call field 'GetPromptLogPath' (a nil value)»
